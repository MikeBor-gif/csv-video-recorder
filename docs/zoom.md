# Зум и API

## Запись событий

Первое нажатие F5 начинает приближение вокруг мыши, второе — отдаление. Удержание клавиши не создаёт повторных событий, страница не перезагружается. Короткое зелёное или розовое кольцо подтверждает переключение. Состояние сохраняется после навигации, включая события из вложенных iframe.

Программный hook выполняет тот же toggle и возвращает Promise с принятым событием:

```python
page.evaluate("() => window.__zoomAt(640, 360)")  # in
# Действия сценария во время приближения.
page.evaluate("() => window.__zoomAt(640, 360)")  # out
```

Координаты задаются в пикселях viewport текущего документа. Viewport и размер записи совпадают: 1280×720. Флаг `--zoom-demo` использует фактическую позицию курсора во время ввода поискового запроса.

## Sidecar

Если есть события, рядом с `ACME.webm` создаётся `ACME.webm.zoom.json`:

```json
{
  "viewport": {"width": 1280, "height": 720},
  "fps": 25,
  "zoom_factor": 2.0,
  "ramp_sec": 0.5,
  "events": [
    {"t": 3.0, "x": 640, "y": 360, "type": "in"},
    {"t": 8.0, "x": 640, "y": 360, "type": "out"}
  ]
}
```

`t` — секунды относительно начала видео. Рекордер добавляет необязательный объект `calibration`: короткий цветной маркер в начале записи позволяет обработчику согласовать часы событий с реальными кадрами.

События идут по времени и чередуются `in`/`out`. Старые sidecar, где у всех событий нет `type`, читаются как чередование начиная с `in`; смешанный формат отклоняется. Масштаб — от 1 до 10, fps и ramp должны быть положительными, числа — конечными, координаты — внутри viewport.

Зум использует smoothstep easing; crop ограничен кадром. Поддержаны несколько пар и прерванные переходы. Если последнего `out` нет, приближение сохраняется до конца видео. Ramp округляется до кадров: `max(1, floor(ramp_sec * fps + 0.5))`.

Без событий sidecar не создаётся. При успешной перезаписи обычного ролика старый sidecar удаляется.

## Обработка через CLI

Для локальной обработки нужны ffmpeg с VP9 и ffprobe; в Docker они установлены.

```bash
python apply_zoom.py --video video/ACME.webm
python apply_zoom.py --video video/ACME.webm --dry-run
python apply_zoom.py --video video/ACME.webm --ffmpeg /usr/bin/ffmpeg
```

Результат: `video/ACME.zoomed.webm`. Опции `--output` и `--sidecar` позволяют указать другие пути. Исходник не перезаписывается. Без sidecar или при пустом `events` результат — побайтовая копия, ffmpeg не запускается. Неверный sidecar считается ошибкой.

`--dry-run` печатает команду без кодирования и не требует ffmpeg. Для калиброванного sidecar это предварительная команда: реальный запуск уточняет времена по маркеру.

Обработчик принимает WebM, сохраняет разрешение, кодирует видео в VP9, имеющееся аудио — в Opus. Выход публикуется после успешного кодирования и проверки; при ошибке временные файлы удаляются.

## HTTP API

Базовый адрес: `http://localhost:8000`.

| Метод и путь | Результат |
|---|---|
| `POST /upload` | Multipart `file`, `company_name`, необязательный `zoom` |
| `GET /get_video_url?company_name=...` | URL оригинала; 404 для неизвестной компании |
| `GET /jobs/<id>` | Статус, `original_video_url`, `processed_video_url`, `error` |
| `POST /jobs/<id>/process` | Синхронная обработка задачи |
| `GET /media/<filename>` | Видео с поддержкой Range-запросов |
| `GET /videos` | Список записей компаний |
| `GET /health` | 200 при доступной БД, иначе 503 |
| `GET /` | Описание сервиса и список маршрутов |

```bash
curl -F "file=@video/ACME.webm" -F "company_name=ACME" -F "zoom=@video/ACME.webm.zoom.json" http://localhost:8000/upload
```

Без `zoom` ответ содержит `company_name` и `video_url`. С sidecar добавляется `job_id`; далее вызовите `POST /jobs/<job_id>/process`. Ответ успешной обработки содержит `status: "completed"` и `processed_video_url`.

`UploadVideo(server_url, video_path, company_name)` автоматически отправляет найденный sidecar, вызывает обработку и возвращает готовый URL. Без sidecar возвращает оригинал. `GetVideoURL` всегда возвращает оригинал; `PreviewVideo` открывает переданный URL в Chromium.

Статусы: `pending` → `processing` → `completed` или `failed`. Неуспешную задачу можно повторить; completed возвращает прежний результат, processing — HTTP 409. После аварии истёкший processing переводится в failed при GET/process. Неизвестный UUID — 404, ошибка обработки — 500, timeout — 504.

Каждая задача читает неизменяемую копию исходника и sidecar. Повторная загрузка компании обновляет `videos`, но не подменяет вход существующей задачи. URL результата и статус сохраняются в `jobs`. Имена результатов зарезервированы: конфликтующая загрузка получает другое имя. Snapshot и промежуточные файлы закрыты от HTTP-доступа.

Обычные загрузки допускают `.webm`, `.mp4`, `.ogg`, `.mov`; загрузка с `zoom` требует `.webm`. Ошибки API возвращаются как JSON с полем `error`: 400 — неверные данные, 413 — превышен размер. Подробности ошибок обработки доступны в логах сервиса.

## Настройки

Значения для контейнера задаются в `.env`; пример — [.env.example](../.env.example).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DB_NAME`, `DB_USER`, `DB_PASSWORD` | `videos`, `video_user`, `video_pass` | База и учётные данные локального стека |
| `MAX_UPLOAD_MB` | `512` | Лимит загрузки |
| `FFMPEG_PATH` | `ffmpeg` | Путь к ffmpeg |
| `ZOOM_PROCESS_TIMEOUT` | `300` | Лимит кодирования, секунды |
| `ZOOM_HTTP_TIMEOUT` | `600` | Apache/WSGI timeout; минимум на 120 секунд больше лимита обработки |
| `WEB_SERVICE_LOG_LEVEL`, `ZOOM_LOG_LEVEL` | `INFO` | Логи сервиса и обработчика |
| `QSCRIPT_LOG_LEVEL` | `INFO` | Логи локального рекордера и клиента |

При изменении `ZOOM_PROCESS_TIMEOUT` задайте то же значение локальному клиенту; его HTTP timeout включает запас 120 секунд. Timeout клиента не означает остановку обработки: проверьте `GET /jobs/<id>`. `VideoClientError` содержит идентификатор задачи.
