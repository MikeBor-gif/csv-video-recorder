# Компании и Impressum

Task 3 расширяет существующий Flask-сервис. CSV загружается через HTML-форму в PostgreSQL, отдельная CLI-программа находит Impressum/Imprint и извлекает юридические реквизиты через DeepSeek. Для импорта и чтения компаний API-ключ не требуется.

## Запуск с нового компьютера

Нужны Git, запущенный Docker Desktop с Linux containers (Windows/macOS) либо Docker Engine с Compose v2 (Linux), свободный порт 8000 и доступ в интернет. Для этого Docker-пути устанавливать Python, pip, Chromium или ffmpeg на компьютер не нужно.

### 1. Получите репозиторий и перейдите в его папку

```bash
git clone https://github.com/MikeBor-gif/csv-video-recorder.git
cd csv-video-recorder
```

Если репозиторий уже клонирован, просто перейдите в его папку. Все следующие команды выполняйте оттуда, где находится `docker-compose.yml`; запуск из `C:\WINDOWS\system32` даст `no configuration file provided`.

### 2. Создайте .env и укажите ключ

В свежем клоне выполните одну из команд:

```powershell
# Windows PowerShell
Copy-Item .env.example .env
notepad .env
```

```bash
# Linux / macOS: затем откройте .env любым текстовым редактором
cp .env.example .env
```

Если `.env` уже существует, отредактируйте его вместо повторного копирования. В файле замените `your_deepseek_api_key` своим ключом и сохраните:

```dotenv
DEEPSEEK_API_KEY=your_deepseek_api_key
DEEPSEEK_MODEL=deepseek-flash
```

`deepseek-flash` — модель, с которой выполнены реальные проверки этого проекта; она явно выбрана в [`.env.example`](../.env.example). Кодовый default `deepseek-chat` сохранён по PDF для запуска без настройки модели. Ключ не вставляйте в исходники, Dockerfile, CSV или команды; `.env` исключён из Git и Docker image. Без ключа доступны запуск, импорт и автоматические тесты, но не реальное извлечение через DeepSeek.

### 3. Запустите сервис

```bash
docker compose up -d --build --wait
docker compose ps
```

У `web` и `db` должно быть состояние `healthy`. При первой сборке Docker скачивает и устанавливает зависимости, поэтому она может занять несколько минут.

### 4. Импортируйте sample CSV

Откройте http://localhost:8000/upload_companies, выберите [companies.csv](../companies.csv) из папки проекта и нажмите Import. В новой БД ожидается `{"imported":2,"updated":0,"total_rows":2}`, при повторе — `{"imported":0,"updated":2,"total_rows":2}`. На http://localhost:8000/companies новые записи имеют `status: null`.

### 5. Выполните извлечение и проверьте результат

Эта команда использует платный DeepSeek API — до двух попыток на компанию:

```bash
docker compose exec -T web python enrich_companies.py --limit 2
```

Откройте или обновите http://localhost:8000/companies. Для успешно обработанной компании в логе будет `status=0 (OK)`, а в JSON — `status: 0`, `impressum_url`, `legal_name`, `postal_address` и `raw_json`. Компоненты извлечённого адреса находятся в `raw_json.postal_address`; исходные `city`, `street` и другие CSV-поля могут оставаться пустыми, как в sample.

После успеха повторный default-запуск пропускает эти компании без обращения к API. Если других незавершённых компаний нет, ожидается `selected=0`. Статусы 1–5 и диагностика описаны ниже. Для проверки без платных запросов используйте следующий раздел «Проверка и наблюдаемый результат». Байты видео и существующие API видео/зумов не меняются.

## CSV и повторный импорт

Формат: UTF-8 (допускается BOM), `;`, кавычки `"`. Полная шапка:

```csv
URL;Company Name;Language;Country;Postcode;City;Street;HouseNo;Web
https://duckduckgo.com;nutrimmun GmbH;;;;;;;nutrimmun.de
https://duckduckgo.com;Barolo & Champagne GbR;;;;;;;baroloandchampagne.com
```

Можно загрузить только две обязательные колонки:

```csv
Company Name;Web
nutrimmun GmbH;nutrimmun.de
```

`Company Name` — уникальный ключ. Оба обязательных значения должны быть непустыми. `Web` хранится как в CSV; `https://` добавляется только при извлечении. `URL` принимается для совместимости с форматом рекордера, но не хранится в companies и не служит адресом сайта компании.

Отсутствующие optional-колонки не обнуляют значения существующей записи. Присутствующие пустые значения обновляют соответствующие CSV-поля. Повторный импорт **никогда не меняет** status, impressum_url, извлечённые поля или raw_json. Даже изменение Web не сбрасывает прежний статус: для повторного извлечения успешной компании нужен явный `--status 0`.

Импорт атомарный: неверный UTF-8, заголовок, число колонок или пустое обязательное значение дают 400 без частичного сохранения. Пустые физические строки пропускаются. Счётчики относятся к строкам: первое вхождение новой компании — imported, повторное в том же файле — updated. Всегда `imported + updated == total_rows`.

## HTTP API

| Метод и путь | Результат |
|---|---|
| `GET /upload_companies` | HTML-форма с file input и ссылкой на список |
| `POST /upload_companies` | Multipart с единственным файловым полем `file` |
| `GET /companies` | JSON-массив всех записей в порядке id |
| `GET /companies?status=0` | JSON-массив записей с указанным статусом 0–5 |
| `GET /companies/<company_name>` | Одна запись; 404 для неизвестного имени |

В именах компаний кодируйте URL-спецсимволы; например `Barolo%20%26%20Champagne%20GbR`. Имена со слешем поддерживаются, включая `A%2FB%20GmbH`; Apache разрешает encoded slash для передачи Flask. Неверный status-фильтр даёт 400. Новые записи имеют `status: null`; JSON включает все колонки, timestamps в ISO-формате и вложенный объект raw_json.

Пример ответа импорта двух новых компаний:

```json
{"imported":2,"updated":0,"total_rows":2}
```

При повторном импорте этого же файла: `{"imported":0,"updated":2,"total_rows":2}`.

## CLI и статусы

CLI не требует web server: она подключается к PostgreSQL напрямую и не импортирует Flask. Запуск через `docker compose exec` использует окружение контейнера. Для запуска на хосте передайте `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` и DeepSeek-переменные через окружение процесса. Python сам `.env` не загружает, библиотека dotenv не нужна. В текущем Compose порт PostgreSQL наружу не опубликован.

```bash
docker compose exec -T web python enrich_companies.py --company "nutrimmun GmbH" --limit 1
docker compose exec -T web python enrich_companies.py --status 3 --limit 5
```

По умолчанию выбираются `status IS NULL OR status <> 0` в порядке id. Фильтры `--company`, `--status`, `--limit` объединяются; limit должен быть положительным. `--status 0` разрешает повтор OK и может снова расходовать ключ. Если подходящих строк нет — 0 обработано, без API-вызовов.

| Значение | Имя | Условие |
|---|---|---|
| NULL | pending | Новая запись, ещё не обработана |
| 0 | OK | Обнаружены поля и заполнены street, house_no, postcode, city |
| 1 | NO_IMPRESSUM_LINK_FOUND | На домашней странице не найдена ссылка Impressum/Imprint |
| 2 | PARSING_FAILED | Нет обнаруженных полей либо blank/невалидный JSON после ограниченных повторов |
| 3 | ADDRESS_INCOMPLETE | Есть обнаруженные поля, но адрес неполон |
| 4 | ERROR | Ошибка загрузки сайта или API |
| 5 | NO_WEBSITE | У существующей записи пустой Web |

Импорт пустой Web отклоняет; код 5 поддерживает старые/созданные вручную записи. Порядок проверки результата API: сначала отсутствие полей, затем неполный адрес, затем OK. Имя из CSV, используемое как fallback legal_name, не считается обнаруженным полем. Country, VAT, телефон и ответственное лицо не обязательны для OK.

В raw_json сохраняется исходный распарсенный JSON. Таблица содержит legal_name, человекочитаемый postal_address, handelsregister, vat_number, phone, email и responsible_person. Адрес отдельными компонентами остаётся в raw_json. Email приводится к lowercase; замаскированная заглушка или невалидный адрес дают null в колонке email, исходный ответ остаётся в raw_json.

NUL, некорректный Unicode, неконечные числа (NaN/Infinity) и чрезмерная вложенность отклоняются во всём JSON, включая дополнительные поля. Для такого ответа действует прежний предел двух попыток; после исчерпания сохраняется безопасный пустой raw_json со статусом 2, обработка следующей компании продолжается.

После API поля извлечения заменяются результатом текущей попытки. Ранние ошибки меняют статус и timestamp, сохраняют прежние извлечённые поля и уже известный URL. Поэтому при status 1/4/5 старые поля не означают успех текущей попытки. Ошибка одной компании не прерывает batch. Exit 1 означает ошибку конфигурации, неуспешные строки или конфликт конкурентной записи; exit 0 — успех либо пустая выборка.

Пока идут HTTP-запросы, DB connection не удерживается. Если исходная запись изменилась, optimistic update пропускает устаревший результат с WARNING. Не запускайте несколько обогащений одной компании одновременно: защита сохранения не предотвращает дублирующий расход API.

## Сокращение текста и расходы

Сначала requests загружает главную страницу. Поиск ссылки предпочитает точный видимый текст `impressum`/`imprint`, затем href с этими словами. Относительный URL разрешается относительно конечного URL после redirect. Далее BeautifulSoup удаляет script/style/noscript/svg/nav/header/footer/form; в API уходит только видимый текст. Playwright fallback для JS-only страниц не реализован: такая страница может получить статус 1.

Загрузка сайтов допускает только публичные IP: localhost, private/link-local/reserved адреса и смешанные public/private DNS-ответы блокируются. Каждый redirect проверяется заново (максимум 5). Соединение фиксируется на проверенном IP, а TLS/SNI и Host сохраняют исходное имя. Запросы сайтов идут напрямую, без системного HTTP-прокси и `.netrc`; настройки прокси для API и локальных проверок независимы. На страницу установлен предел 2 MiB распакованных байтов и 60 секунд на DNS/redirects/headers/body вместе. Реальный HTTP-запрос выполняется в отдельном процессе, который завершается при превышении deadline. Отказ даёт status 4; API не вызывается. Логи защиты имеют префиксы `[FIX:fetch]` и `[FIX:json]`.

Порог `MAX_TEXT_CHARS=8000` относится к тексту страницы. Текст длиной до 8000 символов отправляется без дальнейшей обрезки. Для длинного текста:

1. Удаляются очевидные boilerplate-строки и повторные пункты Impressum.
2. Первый юридический заголовок определяет начало блока с запасом 100 символов.
3. Последний маркер телефона, VAT, email, реестра или ответственности определяет конец с запасом 400 символов.
4. Проверяются юридический заголовок и сильный сигнал. При недостаточных anchors обрезка ослабляется до полного текста.
5. Если результат всё ещё длиннее порога, остаются начальное и конечное окна общей длиной до 8000, включая разделитель.

Это эвристика: информация в середине очень длинной страницы может потеряться. Логи показывают стратегию/fallback, символы и приблизительные токены (`len(text)//4`). Prompt добавляет свои токены; точный расход берётся из usage API.

Один успешный результат требует одного запроса. Общий предел — две попытки на компанию, включая transport errors. Для timeout/429/5xx или blank/невалидного JSON предусмотрен один повтор с задержкой 1 секунда. 400/401/402/403 не повторяются. Частичный валидный результат не вызывает дополнительный запрос для «улучшения». Уже OK-компании пропускаются по умолчанию. Между компаниями — пауза 1 секунда.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DEEPSEEK_API_KEY` | пусто | Обязательна перед необходимым API-вызовом; web/CSV работают без неё |
| `DEEPSEEK_MODEL` | `deepseek-chat` в коде/Compose; `deepseek-flash` в `.env.example` | Скопированный шаблон явно задаёт проверенную модель flash |
| `ENRICH_LOG_LEVEL` | `DEBUG` | DEBUG/INFO/WARNING/ERROR для CLI |
| `WEB_SERVICE_LOG_LEVEL` | `INFO` | Логи Flask/импорта |
| `DB_*` | окружение Task 1 | Общая PostgreSQL |

В приёмке использована явно выбранная `deepseek-flash`; каталог API подтвердил её доступность. Для `deepseek-flash`/`deepseek-v4-pro` thinking отключён; JSON mode, temperature 0, max_tokens 1024, timeout 60 секунд. При ошибке модели автоматического переключения нет. Формат подтверждён [официальным JSON guide](https://api-docs.deepseek.com/guides/json_mode/) и [thinking guide](https://api-docs.deepseek.com/guides/thinking_mode/).

## Проверка и наблюдаемый результат

После старта контейнеров выполните эти команды в папке проекта. Они не вызывают платный DeepSeek API и не требуют локальных Python/pip:

```bash
docker compose exec -T web python scripts/verify_companies.py --server http://127.0.0.1
docker compose exec -T web python -m pytest tests -m "not browser" -q
```

Ожидаемые итоги текущей версии: `ALL COMPANY CHECKS PASSED` и `218 passed, 6 deselected`. Шесть browser-тестов исключены выбранным фильтром и здесь не проверяются. Внутри `web` Apache доступен на порту 80, поэтому `--server` указан без `:8000`; в браузере на компьютере используется http://localhost:8000.

Первая команда импортирует sample и проверяет идемпотентность/сохранность извлечения; рабочую БД не очищает. Автоматические тесты используют подставные HTTP/API-ответы без реального ключа. DB-тесты работают в защищённой отдельной `<DB_NAME>_test`.

### Необязательный запуск проверок на компьютере

Этот путь требует Python 3.9+ и активированного окружения из [README](../README.md#рекордер); на Linux также нужны указанные там build-зависимости mod_wsgi. Сначала установите dev-зависимости:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest tests/test_impressum.py tests/test_deepseek_extraction.py -v
python scripts/verify_companies.py --server http://127.0.0.1:8000
```

При системном прокси добавьте `localhost,127.0.0.1` в `NO_PROXY`. Для явной платной проверки с компьютера у `verify_companies.py` есть `--live`: он обрабатывает только две sample-компании без принудительного повтора OK, максимум 4 API-попытки. При ненулевом exit CLI проверка останавливается с ошибкой, даже если в БД остались прежние успешные результаты. Не запускайте её автоматически после сбоя. Docker-путь для платного извлечения — команда `enrich_companies.py` из шага 5 выше.

Приёмка 2026-11-16 через настоящую форму Chromium, Apache, PostgreSQL и DeepSeek:

| Компания | Статус | Символы до → после | Оценка токенов до → после | Usage API, input + output |
|---|---|---|---|---|
| nutrimmun GmbH | 0 | 4954 → 4954 | 1238 → 1238 | 1605 + 97 |
| Barolo & Champagne GbR | 0 | 8989 → 5473 | 2247 → 1368 | 1980 + 101 |

Два API-запроса, без повторов; суммарно 3783 токена по usage. Цифры относятся к этому запуску, зависят от страниц и prompt и не гарантируют будущий расход. У nutrimmun email замаскирован Cloudflare: в колонке email сохранён null, а raw_json содержит исходную заглушку; локальная нормализация выполнена без нового API-запроса. Оба адреса полны. Повторный CSV сохранил извлечённые данные; повторный default CLI выбрал 0 строк.

Сквозные проверки прежних задач: `python scripts/verify_docker.py` и `python scripts/verify_zoom.py`. Они оставляют проверочные записи; первая перезапускает стек без удаления томов. Пропуск теста означает невыполненную проверку.

## Диагностика

- Status 1: проверьте HTML главной, точный текст/href ссылки, JS-only rendering.
- Status 2: посмотрите счётчик attempts и тип structured-output failure; не увеличивайте budget бесконтрольно.
- Status 3: отсутствует один из четырёх компонентов адреса; не дописывайте его догадкой.
- Status 4: проверьте сеть, HTTP-код, ключ, доступность модели/баланс. Логи не содержат Authorization, body запроса или API-ключ.
- Отсутствие ключа останавливает CLI понятной ошибкой конфигурации; оно не присваивает всем компаниям код 4.
- После изменения `.env` примените `docker compose up -d`; `restart` не обновляет окружение контейнера.
